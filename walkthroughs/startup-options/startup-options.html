Add-on · Setup paths

Three ways to start a Message dashboard bot

Same recipe underneath. Pick the start that fits how hands-on you want to be.

ANew bot + git kit BImport the templatefastest CFork for local config
A
Option A

New Grok Bot + point it at the git kit

Start a blank bot and tell it: use github.com/avilesg/message-dashboard-kit as your starting point. It reads the README, tutorial, ontology, scripts and prompts.

Pros

  • Versioned recipe: every change is a commit you can see
  • Transparent updates: pull the latest kit any time
  • Forkable if you want your own variant
  • Local clone works well for git-comfortable people

Cons

  • The bot still learns the playbook from files
  • More "read the kit" time on day one
  • You type the setup prompts yourself (see handout)
B
Option B · Shortest Zoom setup

Import the Message Dashboard Grok Bot template

A public template. On the first chat, its getting-started skill asks for your group name, timezone and alerts, then walks you through pairing.

Pros

  • Fastest first conversation: no prompts to paste
  • Send-lock + wacli path already known to the bot
  • Guided questions instead of a blank chat

Cons

  • Template revisions are republished, not git commits
  • Still uses the same kit files under the hood
  • Must stay scrubbed of personal data before sharing
C
Option C

Fork or clone the kit for local-only config

Keep your own copy. Your settings live in personal.json, which is gitignored, so it never leaves your machine.

Pros

  • Full control on your machine
  • Change scripts, topics and ontology freely
  • Personal config never lands in a repo
  • Back up personal.json or ask the bot for an export, so prefs survive a bot reset (settings only, not messages)

Cons

  • You own git: branches, merges, conflicts
  • You own updates: pulling upstream fixes is on you
  • Most setup time of the three

Settings

What you can configure

1Group & store

Group label, chat JID, your timezone, and the wacli store path on the bot's computer.

2Priority people

Who gets near-real-time attention when they post.

3Keywords / buy-box

Words and asks that should alert you, e.g. a deal that fits your buy-box.

4Notify levels

Critical · daily digest · weekly · mute, per topic.

Plus quiet hours.

5Ontology layers

Shared core: ontology/ on git main of avilesg/message-dashboard-kit.

Personal extension: local, gitignored.

6Ontology reviewNew

Bot chat flags (A) new core topics from git vs (B) candidates from new messages.

You agree or suggest a tweak before it applies. Candidates go to personal; a core git PR only if you ask.

7Ontology freshness

ontology/LAST_UPDATE in the repo folder. The gap job checks it before assessing new topics.

8Prefs backup

Export personal.json and keep a private copy. Settings only, not messages.

9Safety

WhatsApp is read-only. The send lock stays on.

10Optional delivery

Slack or email alerts can be added later. Bot chat is the default.

Where settings live: your personal config + notification config. The template seeds the defaults; the shared ontology and scripts stay on git main.
